[English index](../en/README.md) · [한국어 색인](../ko/README.md) · [日本語索引](../ja/README.md)

**현재 L2S1은 이식 가능하고 관찰 가능한 결정 런타임을 제공한다. 이것만으로 학습된 결정 모델의 정확도·보정 품질·추론 비용 구조를 확보한 것은 아니다.** 요청받은 [5종 비교 글](https://fornewchallenge.tistory.com/1593)을 계기로 검토했다. [Kev의 공식 문서](https://github.com/jaredpalmer/kev#highlights)가 설명하는 결정용 학습과 홀드아웃 보정은 참고할 설계 목표다. 서로 다른 프로젝트의 대표 정확도·속도 수치는 우리 런타임을 통제된 조건에서 측정한 결과가 아니다. 외부 모델 코드나 가중치는 가져오지 않았다.

## 반영한 개선

Laya 채점기의 원본 순서 동률 처리와 실제 수락 답 채점을 수정했다. `raw_top1_accuracy`, `correct_accepted`, `accepted_correct_all`, `nll_hard`, `ece_hard_15`, `by_type`을 출력한다. 누락·실패한 라벨 있는 결정도 계획된 분모에 남기며, 보고서에 채점 코드·입력 해시를 기록한다.

Laya와 공개 JevBench 보고서에 `risk_coverage`를 추가했다. 최대 후보 확률로 원래 argmax를 정렬하고 같은 확률은 한 묶음으로 처리한다. 곡선과 경험적 오류 예산 1%·5%·10%에서의 최대 처리율을 제공한다. 네이티브 후보 질량·동률 제한을 적용하지 않는 별도 진단이며 실제 수락 정책 지표와 구별한다. 테스트 라벨을 보고 계산한 임계값이므로 배포 정책이나 통계적 오류율 보장으로 사용하면 안 된다. 수락 0건의 오류율은 0이 아닌 null이다. Laya의 반복 사례는 별도 캐시 진단 회차로 유지한다.

## 저장 출력 재채점

기존 [typed-decisions 전체 테스트](TYPED_DECISIONS_BENCHMARK.md) 두 모델의 출력 4,000개를 재채점했다. 잘못된 출력은 없었고 기존 원래 정답 수와 수락 집계가 모두 재현됐다. 9월 26일 출력의 오프라인 재채점이며 새 추론·학습·보정·속도 측정이나 정확도 개선 근거가 아니다.

Gemma 4 E2B는 2,000개 중 1,855개를 수락했고 그중 822개가 오답이었다(수락 오류율 44.31%). 테스트 정답을 본 뒤 가장 유리한 확률 임계값을 고르더라도 경험적 오류율 5% 이하에서 남길 수 있는 최대 비율은 120/2,000, 즉 **6%**였다(120개 중 6개 오답). Qwen3 0.6B는 1,112개 수락 중 730개 오답이었다(65.65%). 같은 진단의 최대 처리율은 1/2,000, 즉 **0.05%**였다. 이는 이 두 미보정 모델·작업 설정의 결과이며 모든 L2S1 모델에 적용되지 않는다. 정답은 합성 교사 라벨이고 질문들은 상태를 공유하므로 독립 표본을 가정하는 불확실성 보장도 제시하지 않는다.

간략한 [재채점 근거](../../benchmarks/decision-review-20260927/summary.json)에 입력·채점 코드 해시와 오류 예산별 건수를 기록했다. 전체 곡선은 로컬 `results/decision-review-20260927/`에 생성된다. 모델 로딩 없이 재현할 수 있다.

```sh
cargo build --locked -p l2s1-tools
mkdir -p results/decision-review-20260927
target/debug/l2s1-tools laya-benchmark score \
  --prepared results/typed-decisions-20260926/prepared \
  --predictions results/typed-decisions-20260926/gemma4-e2b/predictions.jsonl \
  --output results/decision-review-20260927/gemma4-e2b.json
```

다른 모델은 `qwen3-06b`로 바꾼다. 원시 추론 파일은 git에서 제외된 로컬 파일이며 간략한 근거에 포함되지 않는다. 지표 회귀 테스트와 도구 clippy 검사는 통과했다. 런타임 스케줄링, 학습된 동적 헤드, 배포용 오류율 보정은 남은 개발 과제다.

## Prefix reuse와 제공된 M5 Max 비교

사용자가 제공한 측정은 2026-09-27 M5 Max, 128 GB, macOS 27.0 (26A428), 전원 연결·High Power 조건이다. 커밋되지 않은 `local/metal-all-benchmarks` 브랜치의 외부 로컬 결과이며, 여기서 재실행하거나 개별 출력을 감사한 결과는 아니다. GGUF/Metal과 MLX는 엔진뿐 아니라 양자화와 프롬프트도 다르다. decision-rules p50은 판단 3개가 든 요청 단위이고 JevBench p50은 항목 단위이므로 합쳐 비교하지 않는다.

Gemma 4 26B-A4B의 decision-rules fresh p50은 506.0 ms, jv는 166.6 ms로 3.04배 차이다. 반면 JevBench는 153.1 대 193.4 ms로 순서가 뒤집힌다. llama.cpp 자체에 원인을 돌리기 전에 작업 구조를 조사할 근거다. 요약의 prefix reuse 적용 시 약 1.5배라는 수치는 상세 행, layout/batch 설정, 실제 재사용 토큰 수가 없다. 규칙을 다시 읽는 비용이 크다는 가설에는 도움이 되지만 그 비중을 입증하지는 않는다. jv HTTP의 0.313–0.457 ms 측정은 jv 전송·파싱 비용이지 L2S1 추론 오버헤드가 아니다.

로컬 코드에서 확인한 문제는 요청 수명이다. 일반 `decide()`는 prefix-reuse 모드에서도 요청 전후에 KV를 비운다. 기존 `shared_state()`는 state를 고정하고 질문을 바꾸므로, 규칙·선택지를 고정하고 state를 바꾸는 작업을 표현하지 못한다. 새 [`shared_decision()` 세션](SEMIF_ALGORITHM.md#fixed-schema-sessions)은 프롬프트·정답·임계값을 바꾸지 않고 이 수명을 제공한다. 배치 경계에 따른 재사용 제한은 유지한다. 이 네이티브 세션 API가 HTTP 풀, 스키마 라우팅 또는 SDK KV 세션을 자동으로 추가하지는 않는다.

속도와 정답률은 별도 과제다. 제공된 M5 결과의 26B는 합성 규칙 판단 36개에서 raw top-1 100%지만 typed-decisions 2,000개에서는 67.5%다. coverage 95.7%, accepted accuracy 68.7%라면 수락한 판단의 31.3%가 오답이다. Prefix reuse로 이 위험을 고칠 수는 없다. 작은 모델의 엔진별 정답률 차이는 프롬프트·템플릿, 토큰, 양자화, 선택지 순서를 통제한 비교부터 해야 한다. 사용자 요청에 따라 MLX 구현은 범위에서 제외했다.

[RTX 3080 JevBench 231문항 검증](JEVBENCH.md#rtx3080-rerun-20260927)에서는 batch 64에서 토큰 6.48–7.20%만 재사용했습니다. 같은 batch의 출력은 보존했지만 Qwen3 0.6B·Gemma 4 E2B 모두 batch 256 fresh보다 느렸고, batch 변경 자체는 일부 top-1을 바꿨습니다. CPU 규칙 픽스처의 이득은 워크로드에 한정되며 최적화할 때 배치 처리량과 정답 변화도 함께 확인해야 합니다.
