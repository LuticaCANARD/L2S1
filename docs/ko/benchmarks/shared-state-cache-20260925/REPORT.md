# 공유 상태 접두사 재사용, 질문 변경

[English](../../../en/benchmarks/shared-state-cache-20260925/REPORT.md) · [한국어](REPORT.md) · [日本語](../../../ja/benchmarks/shared-state-cache-20260925/REPORT.md)

[English index](../../../en/README.md) · [한국어 색인](../../README.md) · [日本語索引](../../../ja/README.md)

커밋되지 않은 변경 사항이 포함된 커밋 `72fdef3eabaae579d640cb7b51d18a29dc83791e`의 현재 작업 트리를 사용하여 RTX 3080(컴퓨팅 기능 8.6)에서 2026-09-25를 측정했습니다. 릴리스 CUDA 빌드는 `sm_86`를 대상으로 했습니다. 두 모델 모두 컨텍스트 2048, 배치/ubatch 32, 4개의 CPU 스레드, 전체 증거 및 두 경로 모두에서 동일한 상태 우선 프롬프트를 사용했습니다. 모델 로딩 및 체크섬 검증은 제외되었습니다.

이 보고서는 해당 로컬 스냅샷을 기록합니다. 이를 포함하는 풀 요청은 최신 `main`를 기반으로 합니다. 아래 타이밍 번호는 이후 트리에서 사용되지 않았습니다.

각 경로는 통화당 하나의 질문을 받았습니다. 16 질문에는 고유한 ID와 지침 텍스트가 있으므로 이후 호출에서는 동일한 전체 프롬프트를 반복하지 않고도 상태 접두사를 재사용할 수 있습니다. 짧은 창고 상태와 200 관련 없는 `packing` 단어가 포함된 버전이 테스트되었습니다. 조건당 측정된 5개의 라운드에는 각각 1회의 워밍업이 있었습니다. 라운드 사이에 경로 순서가 번갈아 나타납니다. 아래 시간은 세션 생성/삭제 및 Rust 준비를 포함하여 전체 실행의 중앙값이지만 로드 및 보고서 직렬화는 제외됩니다. 비율은 최신 중앙값을 공유 세션 중앙값으로 나눈 값입니다.

준비 캐시는 비활성화된 상태로 유지되었습니다. 따라서 `Reused / input tokens`는 토큰화 캐시 적중이 아닌 실제 네이티브 접두사 재사용을 나타냅니다.

관찰된 이득은 변경되지 않은 상태에 대한 여러 질문에 대한 접두사 유지를 지원합니다. 단일 질문에는 재사용이 없으며 측정된 이점도 없습니다. 이는 자동 교차 요청 LRU가 아닌 명시적인 처리 중인 세션입니다. HTTP 구문 분석, 캐시 조회, 제거, 여러 유지 상태 및 메모리 비용이 측정되지 않았습니다. 합성 워크로드에는 품질 라벨이 없으며 운영 환경 대기 시간 또는 정답률을 설정하지 않습니다. 5개 라운드는 이 호스트와 워크로드만을 특징으로 합니다.

<a id="architecture-specific-build-check"></a>
## 아키텍처별 빌드 확인

`scripts/build_cuda_arch.sh 86`는 네트워크 가져오기를 방지하기 위해 기존 로컬 llama.cpp 소스 체크아웃을 사용하여 별도의 `target/cuda-architectures/sm_86/` Cargo 대상 디렉터리에서 완료되었습니다. CUDA 컴파일 플래그에는 `compute_86` 및 `sm_86`만 포함되어 있습니다. 스크립트는 실행 파일 옆에 일치하는 네이티브 라이브러리를 복사하고 `release/run-l2s1`를 생성했습니다. 해당 런처는 RTX 3080에서 3-판단 스모크 요청을 완료했습니다. 로컬 네이티브 로그는 CUDA로 오프로드된 29/29 모델 레이어를 확인합니다. [build log](../../../../benchmarks/shared-state-cache-20260925/build-sm86.log) 및 [smoke 응답](../../../../benchmarks/shared-state-cache-20260925/sm86-smoke.json)를 참조하세요. 반복적인 네이티브 로그는 무시된 로컬 결과에 남아 있습니다. 다른 CUDA 아키텍처는 이 검사에서 컴파일되거나 실행되지 않았습니다.

<a id="rebuild-on-the-pr-branch"></a>
## PR 분기에서 재구축

Commit `0260180a5c950981cb642a3235b750529b7e4c3a`는 깨끗한 PR 작업 트리에서 `scripts/build_cuda_arch.sh 86`를 사용하여 구축되었습니다. 완전한 로컬 llama.cpp 소스 캐시를 사용하여 17분 안에 릴리스 빌드가 완료되었습니다. CUDA 플래그는 `compute_86` 및 `sm_86`만을 대상으로 했습니다. 런처는 일치하는 네이티브 라이브러리를 사용하여 생성되었습니다. 새로운 3-판단 Qwen3 0.6B 스모크 요청이 29/29 모델 레이어가 오프로드된 RTX 3080에서 완료되었습니다. [rebuild 증거](../../../../benchmarks/shared-state-cache-20260925/pr28-sm86-rebuild.json)에는 바이너리, 네이티브 라이브러리 및 로컬 로그 해시, 플래그 및 범위가 포함되어 있습니다. [smoke 응답](../../../../benchmarks/shared-state-cache-20260925/pr28-sm86-smoke.json)에는 백엔드 장치 및 판단이 포함되어 있습니다. 위의 공유 상태 타이밍 테이블은 이 커밋에서 다시 측정되지 않았습니다.
