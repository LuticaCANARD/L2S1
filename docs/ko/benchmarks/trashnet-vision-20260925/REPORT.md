## 더 자세한 특성과 더 낮은 허용 임계값

다음 실험에서는 추론 전에 `experiment-traits-v2.json`에서 `traits_v2`를 동결했습니다. 선택한 테스트 이미지나 요청의 라벨/파일 이름의 예 없이 재료 단서와 구별 사례를 288 단어로 확장합니다. SHA-256는 `beb2a5980ae5ec92cdaec1e073f17905871597cac61f5349fd70d32d81880662`입니다. 6개의 옵션 ID와 설명은 변경되지 않습니다. 동일한 실행 파일인 체크포인트/프로젝터 쌍, 이미지, 주문, CUDA 장치 및 요청 프로토콜이 사용되었습니다. CLI 승인 설정이 `min_top_probability=0.8`에서 `0.5`로 변경되었습니다. `min_candidate_mass=0.05`는 고정된 상태로 유지되었습니다.

`top_option_probability`는 이름을 지정한 응답 토큰 6개에 대한 조건부 softmax입니다. 임계값 0.5는 후보 질량·동점 검사도 통과할 때, 여섯 후보 질량의 절반 이상을 차지한 최상위 옵션을 선택하도록 합니다. 이는 **답이 맞을 보정 확률이 아닙니다**. 임계값을 낮추면 채점 이후 선택·판단 보류가 바뀌지만 모델의 후보 순위는 바뀌지 않습니다. 따라서 이전 프롬프트의 0.5 결과와 `traits_v2`의 0.8 결과는 저장된 점수로 정확히 계산할 수 있습니다. 이 가정적 계산을 모든 실행의 실제 선택과 비교해 검증했습니다.

### 실시간 패스당 처리 비용

| 모델 | 실행별 fresh ms/이미지 | 실행별 직렬 캐시/축약 ms/이미지 | 평균 시간 변화 |
|---|---|---|---:|
| Qwen3-VL | 101.41, 101.44, 102.70 | 103.10, 102.24, 101.88 | 0.55% |
| Gemma 4 | 80.65, 79.16, 79.85 | 78.20, 81.36, 83.83 | 1.55% |
| SmolVLM | 119.86, 124.47, 107.71 | 113.45, 147.19, 113.27 | 6.21% |

측정된 평균은 직렬 캐시/컴팩트 구성 요소에서 더 높았습니다. 속도 향상이 확립되지 않았습니다. SmolVLM은 두 모드 모두에서 패스에 따라 크게 달라졌습니다. 이는 개별 이미지 완성 대기 시간이나 일반적인 속도 보장이 아닌 상주 모델과 하나의 준비 그룹을 사용한 로컬 분할 평균 비용입니다. 두 최종 모드 모두 동일한 바이너리를 사용하여 실시간으로 실행되었습니다.

<a id="isolated-physical-kv-clear-check"></a>
### 격리된 물리적 KV 지우기 확인

`L2S1_FORCE_KV_CLEAR=1`은 엔진별 벤치마크 진단 설정입니다. 같은 브리지·래퍼 호출을 유지하면서 KV가 이미 비어 있어도 물리적으로 0을 채웁니다. 모델별 이미지 120개 전체에서 마지막 네이티브 호출마다 강제 모드는 물리적 초기화 2회·생략 0회, 기본 모드는 초기화 1회·생략 1회를 보고합니다. 세 쌍 모두 logits·확률·질량·순위·판단이 정확히 일치했습니다. 단일 실행 시간은 진단용으로 보존하며, 안정적인 독립 속도 향상을 입증하거나 이전 래퍼 호출 제거의 영향을 측정하지 않습니다.

다양한 이미지, 상태 및 요청 순서, 모든 판단 결과 필드의 정확한 동일성, 웜 캐시 재사용, 캐시 무효화, 잘못된 형식의 이미지, 지연 컨텍스트 오버플로 및 복구를 포함한 세 가지 실제 모델 구성 요소 테스트를 통과했습니다. 동일한 요청 그룹은 라이브 HTTP 공유 메타데이터 계약도 통과했습니다. Metal는 아직 확인되지 않은 상태입니다.

`preserving-ablation-summary.json`은 선별 실행 24회, 최종 3회 반복 시간 측정, 품질·동등성, 진단 카운터 분포, 실제 모델 테스트를 보존합니다. `ablation-config.json`은 변형 플래그 8개를 고정합니다. `python3 benchmarks/trashnet-vision-20260925/evaluate_ablation.py --help`로 모델 조합을 재현합니다. `evaluate_batch.py --candidate-execution-mode fresh --candidate-evidence-transfer compact --candidate-cache-bytes 8388608`은 직렬 구성 요소 비교를 재현합니다. 초기화 진단에는 fresh/full 후보 비교에 `--baseline-force-kv-clear`를 추가합니다. 원시 응답·로그는 Git에서 제외된 `results/vision-ablation-20260926/`에 남습니다.

<a id="component-integration-verification"></a>
### 구성요소 통합 검증

별도의 직렬 사전 설정을 제거한 후 sm_86 CUDA 빌드는 20 라이브러리 테스트와 하나의 CLI 테스트를 통과했습니다. Qwen3-VL, Gemma 4 E2B 및 SmolVLM 각각에서 `real_fresh_vision_cache_and_compact_match_full_and_recover`는 원래 컴퓨팅 설정에서 정확한 구성 요소 동일성을 전달했으며 `real_vision_optimizations_preserve_full_evidence_and_recover`는 최적화된 컴퓨팅 설정에서 전달되었습니다. 이 6가지 라이브 테스트에는 캐시 적중/무효화, 컴팩트/전체 채점, 중복 이미지 재사용, 네이티브 배치 카운터 및 오류 복구가 포함됩니다. CLI 도움말은 결합된 `--vision-optimized` 사전 설정만 표시합니다. 이 기능 검증에서는 실행 가능한 SHA-256 `ff49cff478fc1c9c2e6d5531a31fca4f5d44dd6747595099627ffef15c4d6b0d`를 사용했습니다. 추론 구현 및 최적화 설정이 변경되지 않았기 때문에 처리량을 다시 측정하지 않았습니다. `results/vision-components-20260926/`에서는 로그가 무시된 상태로 유지됩니다.

<a id="reproduce-and-inspect"></a>
## 재현 및 검사

- `evaluate.py`: 고정된 소스 검증, 판단적 선택, 실시간 HTTP 평가, 요약 계산.
- `selection.json`: 고정된 이미지 ID 및 해시.
- `gemma4/observations.jsonl`, `qwen3vl/observations.jsonl`, `smolvlm/observations.jsonl`: 이미지당 하나의 응답 파생 레코드입니다.
- `gemma4/summary.json`, `qwen3vl/summary.json`, `smolvlm/summary.json`: 개수, 클래스별 결과, 대기 시간 및 바이너리/모델/프로젝터 해시.
- `runtime-checks.json`: 9개 실행 모두에 대한 원본 로컬 서버 로그 해시 및 이미지 인코딩 수입니다. 반복되는 원시 로그는 무시된 로컬 결과에 남아 있으며 이 PR에서 제외됩니다.
- `prompts.json`: 정확한 기준선 및 특성 지침, 변경되지 않은 옵션 설명 및 특성 프롬프트 해시.
- `gemma4-traits-v1/`, `qwen3vl-traits-v1/`, `smolvlm-traits-v1/`: 두 번째 실행에 대한 관찰, 요약 및 서버 로그 아티팩트입니다.
- `prompt-comparison.json`: 각 모델에 대해 동일한 순서의 이미지 ID 및 해시, 선택, 실행 파일, 체크포인트 및 프로젝터를 확인하는 감사된 쌍 비교입니다.
- `experiment-traits-v2.json`: 세 번째 추론이 실행되기 전에 더 자세한 지침, 옵션 스키마, 임계값 설정 및 샘플 해시가 고정됩니다.
- `qwen3vl-traits-v2-p50/`, `gemma4-traits-v2-p50/`, `smolvlm-traits-v2-p50/`: 세 번째 실행의 원시 관찰 및 요약.
- `threshold-analysis.json`: 실제 허용된 판단에 대한 검사를 통해 9개 실행 모두에서 쌍을 이루는 임계값을 다시 계산합니다.
