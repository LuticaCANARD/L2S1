## 설정

RTX 3080, 15 GiB RAM 및 4 GiB 스왑이 있는 하나의 4 코어 Linux 호스트에서 한 체크아웃의 동일한 `sm_86` 릴리스 소스를 이전에 비어 있던 별도의 Cargo 대상 디렉터리에 빌드합니다. 전체 로컬 llama.cpp 소스 캐시, `CARGO_BUILD_JOBS=3` 및 `CMAKE_BUILD_PARALLEL_LEVEL=3`를 사용합니다. 소스는 병합된 PR #28(`f61b6e6`)와 이 PR의 컴파일러 캐시 변경 사항입니다. 네이티브 빌드는 `ccache` 4.12.3를 사용합니다. A와 B를 실행하면 Rust 및 C++ 브리지에 대해 `sccache` 0.13.0도 사용됩니다. 이 검사를 위해 두 도구 모두 무시된 로컬 빌드 아티팩트로 압축이 풀렸습니다. 저장소 종속성이 아닙니다.

| 새 빌드 대상 디렉토리 | 캐시 상태 | Rust 래퍼 | 전체 경과 시간 | 네이티브 `ccache` 적중 |
| --- | --- | --- | ---: | ---: |
| A | 캐시 비우기 | `sccache` | 1,749.353 s (29m 09s) | 0/266 |
| B | A 이후 | `sccache` | 171.595 s (2m 52s) | 254/266 (95.49%) |
| C | B 이후 | 없음 | 204.940 s (3m 25s) | 254/266 (95.49%) |

B에서 옵트인 Rust `sccache` 래퍼는 독립 대상 디렉터리 전체에서 Rust 적중 0개와 49 Rust 누락을 보고했습니다. 9개의 히트작은 C/C++ 브리지 컴파일이었습니다. 더 작은 Rust 라이브러리 프로브도 두 개의 서로 다른 대상 디렉터리에서 누락되었지만 동일한 디렉터리 내에서 강제 재구축이 발생했습니다. 따라서 스크립트는 `ccache`를 자동 감지하고 `RUSTC_WRAPPER`를 통해 `sccache` 옵트인을 유지합니다.

B 및 C 런처는 각각 29/29 모델 레이어가 오프로드된 RTX 3080에서 3-판단 Qwen3 0.6B 스모크 요청을 완료했습니다. 로컬 빌드 로그 및 스모크 stderr은 무시된 `results/compiler-cache-bench-{a,b,c}*` 아티팩트에 있습니다. 실행 B와 C는 254 네이티브 캐시 적중으로 각각 A보다 빠른 10.2x 및 8.5x였습니다. 이는 반복된 통계적 시도가 아닌 설정당 한 번의 실행입니다. 캐시 적중 횟수 및 속도 향상은 이 호스트, 소스 스냅샷, 컴파일러 버전 및 웜 캐시를 설명합니다. 그들은 다른 머신의 빌드 시간을 예측하지 않습니다. 빈 캐시 A 실행은 이전 17분 캐시되지 않은 빌드보다 느렸지만 이는 별도의 실행이었고 차이점은 캐시 래퍼로 격리되지 않았습니다.
