# 画像分析と思考後の判断デモ

[English](../en/IMAGE_DEMO.md) · [한국어](../ko/IMAGE_DEMO.md) · [日本語](IMAGE_DEMO.md)

[English index](../en/README.md) · [한국어 색인](../ko/README.md) · [日本語索引](README.md)

Web の `/demo` で写真やテキストの状態を選択し、構造化された判断を確認できます。記録例は実際のモデル実行結果です。ページを開いたり記録ボタンを押したりしても、モデルを再実行しません。公開の静的サイトには推論サーバーがないため、新しい入力のリアルタイム分析は以下のローカル環境で実行します。

写真の例では、材質（choice）、主な物体が 1 つか（binary）、透明度（ordinal）を判断します。自由形式の説明文を生成するデモではありません。テキスト入力では `direct` または `thinking` を選べます。`thinking` は実際の思考トークンを生成してから候補を評価します。画面には生成トークン数と完了状態を表示します。現在は Qwen3 dense テキストモデルの単一トークン候補経路に対応し、写真モデルの thinking には対応しません。

<a id="로컬-실행"></a>
## ローカル実行

画像に対応した GGUF、同じモデルのプロジェクター、ビルド済みの L2S1 実行ファイルが必要です。CUDA の例は以下のとおりです。CPU では `--device cpu` を選んでください。

```sh
./target/release/l2s1 --model /path/to/vision-model.gguf \
  --mmproj /path/to/mmproj.gguf --device cuda \
  --listen 127.0.0.1:8080
```

テキストの thinking も実行するには、別のターミナルで Qwen3 テキストサーバーを起動します。

```sh
./target/release/l2s1 --model /path/to/Qwen3-0.6B-Q8_0.gguf \
  --device cuda --listen 127.0.0.1:8081
```

Web 開発サーバーを起動します。

```sh
cd web
npm ci
npm run dev
```

`http://127.0.0.1:5173/demo` を開き、画像をアップロードして **내 로컬 모델로 분석（自分のローカルモデルで分析）** を押します。状態 JSON と質問・候補 JSON を編集できます。入力やポリシーを変更すると前の結果は消去されます。JPEG、PNG、WebP の最大 8 MiB に対応します。コンテキスト上限を超えるとサーバーがエラーを返し、写真を切り取って分析できたかのようには表示しません。写真のサイズ、質問数、状態を減らすか、サーバーのコンテキストを増やして再実行してください。

Vite 開発サーバーの同一サイトのプロキシは、写真の `/inference` を `127.0.0.1:8080` に、テキストの `/text-inference` を `127.0.0.1:8081` に接続します。ブラウザーで任意の外部推論 URL を入力する操作はありません。静的ビルド・preview には推論プロキシがなく、実行記録は確認できますが、リアルタイム実行には別の同一サイトのプロキシが必要です。

<a id="수락-기준과-실패-이유"></a>
## 採用基準と失敗理由

候補内で許容する不確実性の割合 `epsilon` を入力すると、`min_top_probability = 1 - epsilon` に変換します。UI の 2 つの数値は同じ採用基準を表します。**この設定は実際の正解に対するエラー率を保証しません。** 候補間の相対確率は正解確率ではなく、業務で許容する実際のエラー率は別の正解データで検証する必要があります。

`min_candidate_mass` も独立して指定できます。候補間の確率が高くても、モデルが候補コード全体にほとんど確率を割り当てない場合は判断を保留できます。同点も保留します。サーバーは標準の `abstention_reasons` コードを保持し、カスタムの説明を `reason_messages` に別途返します。`reasoning_limit`、`native_failure` のカスタム文言も元のエラーと一緒に表示します。失敗理由の編集でエラーを隠したり、成功に変えたりはしません。

出力には `option_probability`、`candidate_mass`、レベルの期待値、保留理由、完全な JSON を表示します。スコアは正解確率や意味の損失率ではありません。保留した選択値は `null` ですが、候補のスコアは確認できます。

<a id="요청과-기록"></a>
## リクエストと記録

[examples/image-analysis.json](../../examples/image-analysis.json) は写真についての 3 つの質問を含むデフォルトのリクエストです。写真入力には `media: [{"id":"photo","type":"image","data_base64":"..."}]` を追加し、`POST /v1/decisions` に送ります。各質問の `media_ids` は `photo` を参照します。テキストの質問には `media_ids: []` を使います。

Web の記録は `web/static/demo/recorded.json`、`text-direct.json`、`text-thinking.json` に保存します。リクエスト・応答・モデル・実行時刻・写真の出典を一緒に保持し、`sample.jpg` を表示します。モデルの重みは Web に含めません。写真はデータセット ZIP の最初の glass 項目 `glass192.jpg` をそのまま使いました。出典のラベルは **glass** ですが、実際の Qwen3-VL-2B 実行は **metal** を選び、誤判定しました。UI ではこの違いを目立つように表示します。採用された高いスコアも正解を保証しません。物体数と透明度はこのデータセットの正解ラベルではないため、正確さは主張しません。1 枚の例は正解率の評価の代わりにはなりません。画像の出典とライセンスは[画像の表記](../../web/static/demo/THIRD_PARTY_NOTICE.txt)にあります。

Web の元の契約 playground は合成スコアの例です。`/demo` の **実際のモデル実行記録**と**直前に実行したローカル推論**とは区別して表示します。
