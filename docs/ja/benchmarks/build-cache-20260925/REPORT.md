## セットアップ

RTX 3080、 15 GiB RAM、および 4 GiB スワップを備えた 1 つの 4 コア Linux ホスト上で、1 つのチェックアウトから同じ `sm_86` リリース ソースを、以前は空だった個別の Cargo ターゲット ディレクトリにビルドします。完全なローカル llama.cpp ソース キャッシュ、`CARGO_BUILD_JOBS=3`、および `CMAKE_BUILD_PARALLEL_LEVEL=3` を使用します。ソースは PR #28 (`f61b6e6`) とこの PR のコンパイラ キャッシュの変更をマージします。 ネイティブ ビルドは `ccache` 4.12.3 を使用します。実行 A と B も、Rust と C++ ブリッジに対して `sccache` 0.13.0 を使用します。このチェックでは、両方のツールが無視されたローカル ビルド アーティファクトに解凍されました。これらはリポジトリの依存関係ではありません。

| 新しいビルド先ディレクトリ | キャッシュ状態 | Rust ラッパー | 経過時間 | ネイティブ `ccache` ヒット |
| --- | --- | --- | ---: | ---: |
| A | キャッシュを空にする | `sccache` | 1,749.353 s (29m 09s) | 0/266 |
| B | A後 | `sccache` | 171.595 s (2m 52s) | 254/266 (95.49%) |
| C | B後 | なし | 204.940 s (3m 25s) | 254/266 (95.49%) |

B では、オプトイン Rust `sccache` ラッパーは、独立したターゲット ディレクトリ全体で Rust ヒットと 49 Rust ミスを報告しませんでした。その 9 件のヒットは C/C++ ブリッジ コンパイルでした。より小さな Rust ライブラリ プローブも、2 つの異なるターゲット ディレクトリにわたって失敗しましたが、同じディレクトリ内で強制再構築がヒットしました。したがって、スクリプトは `ccache` を自動検出し、`sccache` から `RUSTC_WRAPPER` までのオプトインを残します。

B および C ランチャーはそれぞれ、RTX 3080 上で 3 つの 判断 Qwen3 0.6B スモーク リクエストを完了し、29/29 モデル レイヤーがオフロードされました。ローカル ビルド ログと スモーク stderr は無視される `results/compiler-cache-bench-{a,b,c}*` アーティファクトにあります。実行 B と C は、それぞれ A より 10.2x と 8.5x 高速で、254 ネイティブ キャッシュ ヒットでした。これらはセットアップごとに 1 回の実行であり、統計的な試行を繰り返すものではありません。キャッシュ ヒット数とスピードアップは、このホスト、ソース スナップショット、コンパイラのバージョン、およびウォーム キャッシュを表します。別のマシンのビルド時間を予測するものではありません。空のキャッシュ A の実行は、以前の 17 分のキャッシュされていないビルドよりも遅かったですが、これらは個別の実行であり、違いはキャッシュ ラッパーに分離されませんでした。
