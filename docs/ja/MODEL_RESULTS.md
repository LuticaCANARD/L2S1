これらの実行では、フレッシュ/レガシー実行、コンテキスト 8192、バッチ/ubatch 256 が使用され、LoRA は使用されず、出力 ヘッド または学習された 校正 が使用されました。 Bonsai の実行では、完全な GPU オフロードと 4 つのスレッドを備えた RTX 3080 を使用しました。 Gemma 4 31B は、24 GPU レイヤー、読み取りモード ロード、および 8 つのスレッドを備えた RTX 3060 を使用しました。評価者のバイナリも異なるため、† レイテンシの数値は、相互または元のマトリックスとの制御された速度比較ではありません。彼らのローカルな、ジジグレーションされた証拠は、`results/bonsai-27b-20260924/` および `results/jevbench-gemma31-rust-20260924/` にあります。これらのアーティファクトはリポジトリには含まれません。

‡ 26B の実行では、18 CPU エキスパート レイヤーと 8 つのスレッドを備えた RTX 3060 上で同じ 231 パブリック タスク ID を使用しました。元のマトリックスと † 再実行からの異なるリクエストのシリアル化と評価器のビルドが使用されているため、表は制御されたレイテンシの比較ではなく、個別の実行からのタスク スコアを組み合わせています。すべての 231 判断はエラーや切り捨てなしで完了しました。デフォルトのポリシーは、正しい 191 を含む 220 を受け入れました。 [26B 測定の詳細 ](JEVBENCH.md#gemma-4-26b-a4b-separate-run-2026-09-23) を参照してください。その生の証拠は地元のものであり、認定されています。

Qwen3.5-4B Q8_0 は、元の 22 チェックポイントの測定表で最も高い argmax 正解率 184/231（79.65%）を記録し、Hard 項目は 68/111（61.26%）でした。デフォルトのポリシーは 138 判断を採用し、正解 129、不正解 9 で、採用判断の正解率 93.48%、採用率 59.74% でした。Qwen3.5-9B Q4_K_M は採用率 72.29% で採用した不正解 13、Gemma4 E2B は採用率 90.48% で採用した不正解 58 でした。保留前の正解率、採用判断の正解率、採用率は異なる問いに答えます。

GPT-OSS 20B Q4_K_M は、129 予測の後、`cudaGraphInstantiate` で GPU メモリを使い果たしました。 `GGML_CUDA_DISABLE_GRAPHS=1` では、64.94% 正解率 ですべての 231 と 11,901 MiB のサンプリングされたピークを完了しました。最初の 129 確率分布は、失敗した実行と同一でした。結果を再現するときは、この実行時例外を保持します。

モデルのダウンロードが完了した後、Qwen3.5-4B Q8_0 と Gemma4 E2B を完全に再実行すると、すべての項目に対して同じ確率が生成されました。確認された p50/p95 レイテンシーは、それぞれ 86.99/1139.49 ms および 46.08/699.14 ms でした。テーブルは元のマトリックスのタイミングを保持します。

これらはパブリックサブセットのローカル推論測定であり、公式のフルスイートスコア、ランク、または 本番環境 検証ではありません。レイテンシにはロードとウォームアップは含まれません。小さなモデルはトレーニング コンテキストを超える可能性があります。元の 22-チェックポイント 行列の場合、生の予測、モデル/ソース ハッシュ、メモリ サンプル、失敗した試行の証拠、および独立した 正解率/Brier/ECE 再カウントは、ローカルの gitigned `results/jevbench-matrix-20260923/` ディレクトリにあります。それらはこのリポジトリには含まれていません。測定されたソース スナップショットはそれらのアーティファクトとともに保持され、その後の作業ツリーの最適化はこの凍結された比較の範囲外になります。 [評価方法](JEVBENCH.md)を参照してください。
