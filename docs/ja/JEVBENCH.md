# JevBench 公開評価

[English](../en/JEVBENCH.md) · [한국어](../ko/JEVBENCH.md) · [日本語](JEVBENCH.md)

[English index](../en/README.md) · [한국어 색인](../ko/README.md) · [日本語索引](README.md)

Rust `l2s1-tools jevbench-public` コマンドは、既存の `evaluate_jsonl` サンプルをパブリック [JevBench](https://github.com/fstandhartinger/jevbench) タスクに接続します。その公開スコアラーは、レビューされた上流のリビジョンに従っています。以前に記録された Gemma 4 E2B Q8_0 とマルチモデル マトリックスの結果は、歴史的な Python アダプターからのものです。新しい実行では Rust を使用します。

レビューされたアップストリーム リビジョンは `f79a1cab94ab9a5879383b7ef9ee1805b9dc2d84` です。準備により、別のリビジョンまたはダーティな上流チェックアウトが拒否されます。公開された 3 つの JSONL ファイルには、231 判断 (簡単な 48、オリジナルの 72、ハード 111) が含まれています。これは公開サブセット評価であり、完全な 534 アイテムの評価や公式のリーダーボードの提出ではありません。

<a id="reproduce"></a>
## 再現する

要件: 固定されたリビジョンでのクリーンなアップストリーム チェックアウト、互換性のある GGUF、および CUDA 対応プロジェクト ビルド。評価者は CUDA オフロードを検証します。特定の GPU をさらに必要とする場合は、`--expected-gpu 'RTX 3060'` (または対象のデバイス名) を使用します。ハーネス ファイルとパブリック タスク ファイルには、アップストリームの MIT 通知が保持されます。モデル項は分離されたままになります。

```bash
# On a CUDA host with the Rust and native toolchains configured:
cd /path/to/L2S1
cargo build --release --locked --features llama-cuda --bin l2s1 --example evaluate_jsonl
cargo build --release --locked -p l2s1-tools

git clone https://github.com/fstandhartinger/jevbench.git ../upstream-new
git -C ../upstream-new checkout --detach f79a1cab94ab9a5879383b7ef9ee1805b9dc2d84

target/release/l2s1-tools jevbench-public run \
  --jevbench ../upstream-new \
  --evaluator target/release/examples/evaluate_jsonl \
  --model models/gemma-4-E2B-it-Q8_0.gguf \
  --context 8192 --expected-gpu 'RTX 3060' --output ../run-gemma4-new
```

出力ディレクトリはまだ存在していてはなりません。外部推論 API、API キー、または課金対象サービスは使用されません。

CPU/GPU ウェイト配置の場合、ハーネスは `--gpu-layers N`、`--cpu-moe-layers N`、および `--threads N` も受け入れます。 RTX 3060 上の Gemma 4 26B A4B Q4 チェックポイント の場合は、`--cpu-moe-layers 18 --threads 8 --context 8192` を使用します。マニフェストはこれらの設定を記録し、ハーネスは報告された配置をチェックします。これらのオプションを省略すると、ベースラインの配置と 4 スレッドのセットアップが維持されます。オプションの `--model-load-mode read` は、モデルの読み込みのみを変更します。デフォルトの `auto` は自動ロードを保持します。要求されたモードが記録され、検証されます。

<a id="mapping-and-measurement-contract"></a>
## マッピングと測定の契約

- `state`、命令、および 判断基準 のみを推論に渡します。予想される回答、根拠、金の分配、出所を別のスコアリング ファイルに保存します。
- 正規の `labels` 順序を保持します。 `choice` を順序付けされたオプションにマップし、`noul` を no/yes にマップバックされた確率で false/true にマップし、`score` を数値 順序付き レベルに昇順でマップします。
- モデルの 候補間の相対 確率を直接使用します。公式 argmax スコアは、プロジェクトのデフォルトの 判断 ポリシーが判断保留されている場合でも計算されます。そのポリシーの 採用された判断の正解率、間違って受け入れられた回答、および 採用率 を個別に報告します。
- Rust スコアラーは、固定されたアップストリームの `score_task` および `summarize` 定義に従います。 Brier は、両方のバイナリ ラベルを含む完全なマルチクラスの合計を使用します。 ECE は 10 個の等しい幅の信頼度ビンを使用します。保存された公開予測と集計結果は、アップストリームの Python スコアラーと比較されました。
- ベースライン構成: レガシー プロンプト、新規実行、コンテキスト 8,192、バッチ/マイクロバッチ 256、4 つのスレッド、一度に 1 つのリクエスト、FlashAttendant オフ。 LoRA、出力 ヘッド、校正 アーティファクト、またはこれらのアイテムに関するトレーニングはありません。
- 入力オーバーフローはエラーのままであり、切り捨てられることはありません。推論の失敗を保持します。欠落、重複、または不明な結果 ID および候補マッピングの不一致を拒否します。
- ロードと 1 つのウォームアップを除いたローカルの Rust 推論呼び出しレイテンシをレポートします。これには、迅速な準備と推論が含まれますが、HTTP/ネットワーク パスは含まれません。これは公式ボードのリモート エンドポイントのレイテンシではありません。
- ローカルコストは不明 (`null`) であり、ゼロではありません。完全なデータセット、正式なデプロイメントのレイテンシー、およびサポートされている価格基準が利用できないため、全体的な JevBench スコアまたはランクは割り当てられません。

出力には、正確な推論リクエスト、ゴールドを含む元のタスク、生の予測、正規化された JevBench レコード、パブリック層/ファミリー別の公式メトリクスの概要、選択的ポリシーの結果、ログ、コマンド、およびデータ/モデル/評価者のハッシュが含まれます。 `native_candidate_softmax` は確率ソースを識別します。これらの値は、調整された正確性の確率であるとは保証されません。

マッピングテスト:

```bash
cargo test --locked --offline -p l2s1-tools jevbench_public::tests
```

<a id="local-rtx-3080-rerun-2026-09-23"></a>
## ローカル RTX 3080 再実行 (2026-09-23)

新しい 5 モデルの実行では、コンテキスト 16,384 および `--expected-gpu 'RTX 3080'` を使用しました。すべての 1,155 予測は、推論エラーや切り捨てなしで完了し、正解率、Brier、ECE、および 判断保留 の合計の独立した保存予測再カウントに合格しました。 Gemma 4 E2B Q8_0 は 159/231 (68.83%) を獲得しました。 Gemma 3 1B Q8_0 93/231、タイニーラマ 1.1B Q4_K_M 77/231、Qwen3 0.6B Q8_0 73/231、および SmolLM2 135M Q8_0 71/231。これらのスコアでは、デフォルトの 判断保留 ポリシーの前に argmax が使用されます。

公開データセットとスコアリング モジュールは、[Open-Jev レポート ](https://zefan-cai.github.io/open-jev/benchmarks/) で参照されるリビジョンとバイト同一です。これは、ローカル GGUF を使用して L2S1 を評価します。 Open-Jev のトレーニング済みチェックポイントは実行されませんでした。ローカルの完全なレポート (ローカル アーティファクト: `results/jevbench-local-20260923T083530Z/REPORT.md`、コミットされていない) には、層スコア、選択的 正解率、タイミング制限、および再生コマンドが記録されます。生の予測、ソース スナップショット、およびリプレイ証拠は、無視された結果ディレクトリ内のレポートの横に残ります。これは、以下の RTX 3060 マトリックスとは別のものです。

<a id="prompt-order-diagnostics-on-that-rtx-3080-run"></a>
### その RTX 3080 でのプロンプト オーダー診断が実行されます

4 つのポストホック診断ストリームは、JSON フィールド順序 (`state-first`) を変更するか、ID と 判断基準 のペアを持つ 139 選択オプション リストを逆にしながら、各モデル、パブリック タスク セット、および推論設定を固定したままにしました。元のモデルのスコアは、上記の 5 つのモデルの実行からのベースラインです。以下の正解はセマンティック ID であるため、表示された選択肢の位置が変更されても、それ自体は変更された回答としてカウントされません。

| モデル | 変化 | 基準 / 231 | 新測定 / 231 | セマンティックな回答が変更されました | 不正解→正解 / 正解→不正解 |
| --- | --- | ---: | ---: | ---: | ---: |
| Qwen3 0.6B Q8_0 | まずステート | 73 | 78 | 73/231 | 29 / 24 |
| Qwen3 0.6B Q8_0 | 選択順序が逆になる | 73 | 76 | 131/139 | 29 / 26 |
| Gemma 4 E2B Q8_0 | まずステート | 159 | 151 | 50/231 | 15 / 23 |
| Gemma 4 E2B Q8_0 | 選択順序が逆になる | 159 | 157 | 33/139 | 9 / 11 |

4 つのストリームはすべて、推論エラーや切り捨てなしで完了しました。これは、プロンプトとオプションの表示によってこれらのチェックポイントの出力が変更される可能性があるという証拠です。これは、独立した継続的な改善テストや、状態優先が他のモデルにとって優れているという主張ではありません。ローカルの gitignored `results/jevbench-diagnosis-20260923/REPORT.md` には、完全な診断、コマンド、保存された予測が保持されます。従来の順序はデフォルトのままです。

<a id="multi-model-comparison"></a>
## 複数モデルの比較

[記録済みのモデル比較](MODEL_RESULTS.md#recorded-model-comparison)は、9 月 23 日に完了した RTX 3060 の測定表をまとめています。22 の GGUF チェックポイントが各 231 項目を評価し、完了した実行にエラーはありませんでした。ランタイム設定は 23 種類です。GPT-OSS は CUDA Graphs を有効にすると失敗し、`GGML_CUDA_DISABLE_GRAPHS=1` で完了しました。最初の失敗も根拠として残します。レイテンシは各設定に属し、別の実行と混合しないでください。

完全なレポート、CSV、生の予測、モデル計画、ランタイム ハッシュ、および測定されたソース スナップショットは、ローカルの gitignored `results/jevbench-matrix-20260923/` ディレクトリにあります。それらはこのリポジトリには含まれていません。 Qwen3.5-4B Q8_0 は、184/231 (79.65%) でこの選択されたマトリックスをリードしました。モデルのダウンロードが完了した後の完全な再実行では、そのモデルと Gemma4 E2B のすべての確率が正確に再現されました。スナップショットは、後続の作業ツリーの変更とは関係なく、この比較で使用された凍結されたビルドを記録します。

`l2s1-tools jevbench-matrix download/run` は、固定プランをダウンロードするか、パブリック エバリュエーターを通じて利用可能なチェックポイントをシリアルに実行します。 `l2s1-tools report-jevbench-matrix` は、保存された予測をゴールド ラベルに対して再計算し、レポートを作成する前に共有リクエスト/評価者のハッシュをチェックします。再生成するには、ローカル モデル プラン、モデルごとの完全な実行ディレクトリ、および `matrix-status.json` が必要です。生成されたレポート、実行アーティファクト、およびホスト固有のプランは、ソースとともにバージョン管理されるのではなく、ローカルに残ります。

## Gemma 4 リビルド確認 (2026-09-23)

現在の Rust ソースと ネイティブ C++ ブリッジは、固定された llama.cpp CUDA ライブラリを再利用して、RTX 3060 ホスト上の別のディレクトリに新たにコンパイルされました。 Gemma 4 E2B Q8_0、E4B Q8_0、および E4B Q4_K_M はそれぞれ、上記のベースライン設定で同じパブリック 231 アイテムを完了しました。それぞれ、157/231 (67.97%)、 177/231 (76.62%)、179/231 (77.49%) のスコアを獲得しました。すべての 693 候補確率ベクトルと 判断 値は、前の RTX 3060 行列と正確に一致しました。推論エラーや切り捨ては発生しませんでした。

リビルド レポート (ローカル アーティファクト: `results/gemma4-rebuild-20260923T103912Z/REPORT.md`、コミットされていない) には、前後の比較、レイテンシ、ソース ハッシュとバイナリ ハッシュ、およびビルド ログが記録されます。デフォルトのテストは 49/49 に合格しました。ラマ機能スイートは、18 を無視して 59 テストに合格し、その後、個別に実行された Gemma 4 CUDA 統合テストと 6 つのマッピング テストに合格しました。これらの結果は、凍結されたソースとベースライン パスをカバーしています。この再実行では、オプションの最適化モードが有効になっていませんでした。
